# Loki through Zetaris, run live

Run on 2026-10-25 with Zetaris 2.4.3 (docker), a real Loki 3.2.0, and Overwatch generated by discovery with Zetaris as the data layer.

**Discovery.** `discover(loki={"url": ...}, zetaris=True)` registered Loki inside the Zetaris source (`rest: {loki: <url>}`), marked the direct Loki source `internal` (hidden from the Investigator, kept for the Watcher's fast checks), and rewrote the catalog to tell the model to use `logql <expression>`. The console's data layer read: `zetaris: overwatch (history and telemetry), loki (via logql)`.

**What the Zetaris source did.** A `logql {app="api"} |= "ERROR"` query created a Zetaris REST table over `/loki/api/v1/query_range` and a view over it; it returned the three error lines with their labels, nanosecond timestamps and text. A metric query (`logql sum(count_over_time(... [2m]))`) returned the time series. Loki must be reachable from the Zetaris container (the host alias is used for `localhost`).

**The investigation.** 14 error lines were pushed for one service. The `api_log_errors` check fired and an incident opened. The Investigator then ran, all with `source = zetaris`:

| step | query | rows |
|---|---|---|
| 1 | `logql {service_name="api"} \|~ "(?i)(error\|exception\|fail\|timeout)"` | 17 |
| 2 | `logql {service_name="payments"} \|~ ...` | 2 |
| 3 | `logql {service_name="payments"} \|~ "(database\|db\|connection\|pool\|...)"` | 2 |
| 4 | `SELECT * FROM overwatch.check_samples WHERE service = 'payments' ...` | 9 |
| 5-6 | two more `logql` queries on payments | 2, 2 |
| 7 | `SELECT * FROM overwatch.check_samples WHERE service = 'api' ...` | 12 |

It concluded at 90% confidence that payments had exhausted its connection pool (20/20 in use) and that this broke the API's calls to it, which is what the log lines said. One investigation mixed Loki logs and Overwatch's own history in the same query layer.

**Not covered.** Kubernetes stays a live source (Zetaris would need a bearer-token REST source over the cluster's own certificate). Loki with authentication through Zetaris was not tried; `loki_headers` (tenant) is passed to the REST table.
